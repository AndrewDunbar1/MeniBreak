THE CLAIM WE WOULD LIKE TESTED. In our institutional meningioma cohort, *where* copy-number breakpoints fall carries recurrence-risk information beyond WHO grade, integrated grade, and arm-level copy-number alteration - and unlike those markers, it gets stronger at longer horizons. We have distilled that into a fixed nine-window "breakpoint hot list". That hot list is the one thing we are asking you to test. Everything else is secondary.

Repo (I have shared access): https://github.com/AndrewDunbar1/MeniBreak

WHAT YOU NEED

Two CSVs - no clinical data required to start:

segments.csv sample_id, chromosome, start, end, event outcomes.csv sample_id, recurrence_time (IN YEARS), recurrence_event (1/0)

Full schema, including optional columns: docs/INPUT_SPEC.md in the repo.

THE RUN

git clone https://github.com/AndrewDunbar1/MeniBreak.git && cd MeniBreak
pip install -r requirements.txt

# 1. Is your assay fine-grained enough for this to mean anything?
python apply/check_resolution.py --segments YOUR_segments.csv

# 2. The test: the fixed hot list, scored with ZERO parameters fitted
#    on your data
python apply/validate_fixed_panel.py \
    --segments YOUR_segments.csv \
    --outcomes YOUR_outcomes.csv \
    --out results/validation

Please run step 1 first and stop if it says TOO COARSE. The windows are ~2.8 Mb, so a platform that localises breakpoints coarsely (methylation-derived copy number is the usual case) cannot test this - a weak result there tells us about the assay, not the biology. If it says SUITABLE or MARGINAL, continue.

Then send back the two files in results/validation/ : fixed_panel_performance.csv and panel_window_occupancy.csv. Neither contains patient-level data.

HOW TO READ YOUR NUMBER

For reference, on our derivation cohort the fixed hot list scores 0.690 / 0.772 / 0.785 at 3 / 5 / 7 years, against arm-level SCNA at 0.777 / 0.766 / 0.767.

One important caveat, so nobody over-reads it: those are an OPTIMISTIC ANCHOR, not an expectation. The nine windows were chosen using our cohort's outcomes, so scoring them there is partly circular. A lower number in your cohort is the expected result, not a failure. The clean comparison is the arm-level SCNA figure the tool prints alongside your result - that one is computed on your data and your folds, and carries none of our bias. Details in docs/WHICH_MODEL.md.

IF THE HOT LIST DOESN'T HOLD UP

That is a real and publishable answer, and we would rather know. If it comes out flat, there are three progressively looser fallbacks, in this order:

1. --score refit

 Same fixed windows, but let the weights be re-fitted on your cohort. Tests
 whether the window SET is informative even if our unweighted scoring is not
 calibrated to your population.

2. --panel-set rule

 An 11-window variant of the list.

3. python apply/menibreak_panel.py ...

 Ignore our list entirely and let the method rediscover windows inside your
 own cross-validation folds. This answers the broader question: does YOUR
 cohort have recurrent prognostic breakpoint structure at all, and does it
 land anywhere near ours (we would look for chr1:118.75-125.00 Mb)?

Only worth doing if the primary test is unconvincing - we would rather have a clean negative on the primary test than a positive found after four attempts.

OPTIONAL AND SECONDARY: THE FULL MODEL LADDER

Entirely separate from the pass/fail question above, and only if you have the clinical fields to hand: adding a third CSV runs every model in our report on your cohort at once - the two grade comparators, arm-level SCNA, the hot list, the combined SCNA + hot list, and the larger clinical + SCNA + breakpoint models (9 models x broad/restricted x 3 horizons).

python apply/menibreak_panel.py \
    --segments YOUR_segments.csv --outcomes YOUR_outcomes.csv \
    --clinical YOUR_clinical.csv --out results/full_ladder

clinical.csv needs only sample_id; every other column is optional and the tool scores whatever your columns support, logging what it skipped. The useful ones are age, mitoses, gtr, prior_rt, adj_rt (unlock the clinical models); who_grade, integrated_grade (unlock the grade comparators); and primary, rt_induced, angiomatous (unlock the restricted surgical subset). Full table in docs/INPUT_SPEC.md section 3.

Grade is read as a comparator only - it never enters a genomic model as a predictor, which is enforced in code rather than left to convention.

This is the interesting exploratory run: it shows whether breakpoints add anything on top of YOUR grading and copy-number data, not just on top of ours. But please treat the hot-list result above as the headline either way - a clean answer on one prespecified test is worth more than a sweep across nine.
